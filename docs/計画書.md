# WebClass課題締め切り カレンダー自動登録 計画書

作成日：2026-11-03

## 概要

大学のWebClassから課題の締め切りを毎日1回自動で取得し、Googleカレンダーの専用カレンダーに締め切り時刻の予定として登録するPythonプログラムを、自分のWindows PCで動かす。

- **誰のための仕組みか**：WebClassで課題を提出している自分（福知山公立大学の学生）
- **困りごと**：課題の締め切りを確認するには、ポータルにログインしてWebClassを開く必要がある。普段使っているカレンダーには締め切りが入っていないため、予定と並べて見られず、見落としが起きやすい
- **目指す状態**：何もしなくても、新しい課題の締め切りがカレンダーに入り、締め切りの1時間前に通知が届く
- **実現可能性**：高い。ポータルに二段階認証がなく、全コースの課題が「課題実施状況一覧（ダッシュボード）」の1ページにまとまり、CSVでダウンロードできるため。ログインからダッシュボードまでの道順は手動の記録（codegen）で確認済み。残る不確かな点は「開発の最初に確認すること」にまとめた

## 決定事項

この会話で合意した要件は次のとおり。開発中に変える場合は、この表を先に更新する。

| 項目 | 決定内容 |
| --- | --- |
| 取得元 | WebClassの「課題実施状況一覧（ダッシュボード）」。表示は「すべて表示」 |
| ログイン | 大学ポータル（CampusPlan）にログインし、「外部サービス」→「WebClass」（別ウィンドウ）→「» ダッシュボード」とたどる。二段階認証・画像認証なし |
| 取得方式 | Playwrightでブラウザを自動操作する。「CSVダウンロード」でCSVを取得して読む（必要な情報がそろっていることを確認済み） |
| 登録対象 | 締め切りがあるすべての教材（課題以外も含む）。提出済みも含む |
| 過去の課題 | 登録しない。実行時点より後の締め切りだけ登録する。登録済みの予定は残す |
| 登録先 | Googleカレンダーの専用カレンダー（普段のカレンダーと同じ画面に重ねて表示） |
| 予定の時刻 | 締め切り時刻（開始＝終了＝締め切り）。長さ0分が使えなければ締め切り1分前〜締め切り |
| 予定のタイトル | `コース名 課題`。コース名の括弧部分（例：`(2026-後期-月1)`）は外す |
| 予定の説明欄 | 教材名、締め切り日時、最終確認日時 |
| 通知 | 締め切りの1時間前に1回 |
| 提出済みになったとき | タイトルは変えない。通知を消す（予定は残す） |
| 締め切りが変わったとき | 予定の時刻を更新する |
| WebClassから課題が消えたとき | 予定は消さない |
| 実行頻度 | 1日1回、0時 |
| 実行場所 | 自分のWindows PC。タスクスケジューラで、ログオンしていなくても実行する |
| 実行し損ねたとき | 次にPCを起動したときに実行する |
| 失敗したとき | ログファイルに記録し、カレンダーの当日に「⚠課題の取得に失敗」の予定を入れる |
| パスワードの保管 | `.env` ファイル。GitHubには上げない |
| ソース管理 | GitHubのPublicリポジトリ |

## システム構成と処理の流れ

タスクスケジューラが毎日0時に `main.py` を起動し、ログインから同期までを1回の実行で行う。

1. **タスクスケジューラ**：毎日0時に起動
2. **ポータルにログイン**：Playwright・ヘッドレス
3. **ダッシュボード取得**：CSVをダウンロード
4. **課題情報の取り出し**：締め切りありのみ
5. **カレンダーと同期**：新規登録・時刻更新・通知 → 専用カレンダー（1時間前に通知）

どこかの段階で失敗したら、ログに記録し、専用カレンダーの当日に「⚠課題の取得に失敗」の予定を入れる。Googleの認証切れのときはカレンダーに書けないため、Windowsの通知で知らせる。

プログラムは次のファイルに分ける。

| ファイル | 役割 |
| --- | --- |
| `main.py` | 全体の流れをまとめて実行する入口 |
| `webclass.py` | ポータルへのログインと、CSVのダウンロード |
| `parser.py` | CSVから課題情報を取り出す |
| `calendar_sync.py` | Googleカレンダーへの登録・更新 |
| `notifier.py` | ログへの記録と、失敗時の知らせ |

## 機能仕様

### 1. ログインと取得

1. `.env` からポータルのIDとパスワードを読み込む
2. ブラウザ画面を表示しない設定（ヘッドレス）でポータルにログインする（ログインURL：`https://fukuchiyama-web.campusplan.jp/portal/Account/LoginRedirect`）
3. 「外部サービス」ボタン →「WebClass」リンクの順にたどる。WebClassは別ウィンドウで開くので、Playwrightの `expect_popup` で新しいウィンドウを受け取り、その中で「» ダッシュボード」を開く（同じウィンドウ内で開く）
4. 年度は実行日から自動で決める（4月〜翌3月を1年度とする）。表示は「すべて表示」を選ぶ
5. 「CSVダウンロード」ボタンを押してCSVを保存する（Playwrightのダウンロード受け取り機能を使う）。保存先は `output/latest.csv` とし、毎回上書きして最新の1つだけ残す
6. 最後にログアウトしてブラウザを閉じる

参考：codegenで記録したログイン部分（ID・パスワードは消してある）

```python
page.goto("https://fukuchiyama-web.campusplan.jp/portal/Account/Login?ReturnUrl=%2Fportal%2FAccount%2FLoginRedirect")
page.get_by_role("textbox", name="ログインID").fill(LOGIN_ID)
page.get_by_role("textbox", name="パスワード").fill(PASSWORD)
page.get_by_role("button", name="ログイン").click()
page.get_by_role("button", name="外部サービス").click()
with page.expect_popup() as page1_info:
    page.get_by_role("link", name="WebClass", exact=True).click()
page1 = page1_info.value
page1.get_by_role("link", name="» ダッシュボード").click()
```

### 2. 課題情報の取り出し

1件ごとに次の情報を取り出す。

| 情報 | 取り出し元 | 用途 |
| --- | --- | --- |
| コース名 | 「コース名」列（括弧部分を外す） | 予定のタイトル |
| 教材名 | 「教材」列 | 予定の説明欄 |
| 締め切り日時 | 「締切」列（形式：`2026-08-07 23:59`） | 予定の時刻 |
| 提出済みかどうか | 「実施日」列に日時があれば提出済み、「-」なら未提出（確認済み） | 通知の有無 |
| 識別キー | 「コース名＋教材名」（CSVにIDの列はない。2026年度の83件で重複なし） | 同じ課題かどうかの判定 |

締め切りが空欄の教材は対象外とする。CSVは文字コードUTF-8（BOM付き）で、1〜5行目は作成日・年度・学籍番号などの情報、7行目が列名（学部、学科、コース名、教材、締切、実施日、最高点、状態）、8行目以降が教材のデータ。先生が教材名を変えると別の教材として扱われ、予定が2件になる点は許容する。日時はすべて日本時間（Asia/Tokyo）として扱う。

### 3. カレンダーとの同期

識別キーは、予定の非公開の追加情報（Google Calendar APIの `extendedProperties.private`）に保存する。次回からはこのキーで登録済みの予定を探すため、手元にデータベースを持たなくてよい。

| 状況 | 動き |
| --- | --- |
| 締め切りが実行時点より前 | 何もしない（新規登録も更新もしない） |
| 未登録・未提出 | 予定を作り、1時間前の通知を付ける |
| 未登録・提出済み | 予定を作る。通知は付けない |
| 登録済み・締め切りが変わった | 予定の時刻と説明欄を更新する |
| 登録済み・提出済みになった | 通知を消す。タイトルは変えない |
| 登録済み・変化なし | 説明欄の最終確認日時だけ更新する |
| WebClassから消えた | 何もしない（予定は残す） |

何回実行しても結果が同じになる作りにする。実行が遅れても、1日に2回動いても、二重登録にならない。

### 4. 失敗したときの動き

| 失敗の種類 | 例 | 動き |
| --- | --- | --- |
| ログイン失敗 | パスワード変更、ポータルの停止 | ログに記録し、当日の予定に「⚠課題の取得に失敗」を入れる |
| 画面の構造が変わった | CSVの列名が見つからない | 同上。課題0件と区別するため、CSVの列名の有無で判定する |
| Googleの認証切れ | 許可の期限切れ | カレンダーに書けないので、ログに記録する。Windowsの通知も出す |

失敗の予定は1日1件までにする。翌日以降に成功したら、その日の失敗予定は作らない。

## データの扱いとセキュリティ

パスワードや個人情報を含むファイルは、すべてGitHubに上げない。`.gitignore` に最初から書いておく。

| ファイル | 中身 | GitHubに上げるか |
| --- | --- | --- |
| `.env` | ポータルのIDとパスワード、専用カレンダーのID | 上げない |
| `.env.example` | `.env` の項目名だけ書いた見本（値は空） | 上げる |
| `credentials.json` | Google Cloudで発行した、このプログラム用の認証情報 | 上げない |
| `token.json` | 初回の許可で作られる、カレンダー操作用の鍵 | 上げない |
| `logs/` | 実行ログ | 上げない |
| `output/` | 毎回ダウンロードするCSV（学籍番号・点数を含む）。毎回上書きし、最新の1つだけ残す。試作時のダッシュボードのHTMLもここに置く | 上げない |
| `tests/fixtures/` | テスト用のダミーデータ（個人情報をダミーに書き換えたもの） | 上げる |

- パスワードやトークンはコードに直接書かない。ログにも出さない
- ログには課題名と処理結果だけを書き、点数や学籍番号は書かない
- アクセスは1日1回に限り、大学のサーバーに負担をかけない
- 大学の情報システム利用規程で自動アクセスが禁止されていないかを、開発前に確認する

## 実行環境と自動実行

自分のWindows PCで、Windowsのタスクスケジューラ（決まった時刻にプログラムを起動する機能）から毎日0時に起動する。

- **Python**：仮想環境（プロジェクト専用にパッケージを入れる場所、`venv`）を作り、その中の Python で実行する
- **起動方法**：タスクスケジューラから、仮想環境の `python.exe` で `main.py` を起動する。作業フォルダはプロジェクトのフォルダにする

タスクスケジューラで設定する項目は次のとおり。

| 設定 | 値 | 理由 |
| --- | --- | --- |
| トリガー | 毎日 0:00 | 1日1回の実行 |
| ユーザーがログオンしているかどうかにかかわらず実行する | オン | PCにログインしていなくても動かすため。登録時にWindowsアカウントのパスワードが必要（PINでは不可） |
| スケジュールされた時刻にタスクを開始できなかった場合、すぐにタスクを実行する | オン | 0時に電源が切れていたら、次の起動時に実行するため |
| コンピューターをAC電源で使用している場合のみタスクを開始する | オフ | ノートPCのバッテリー駆動中でも動かすため |
| タスクを実行するためにスリープを解除する | オン | スリープ中でも0時に起こすため |
| タスクを停止するまでの時間 | 30分 | ログイン画面で止まったままにならないようにするため |

注意：電源が切れているときは0時に実行されない。この場合は、次にPCを起動したときに実行される。

次の4つの使用に合意済み。これ以外を追加するときは、事前に確認をとる。
